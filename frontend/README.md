# AI Engineer — frontend

React + TypeScript + Vite. Перенесены регистрация, вход, демо-профили, кабинет с протоколами и ролевым доступом, 3D-робот из утверждённого макета. Backend для запуска не нужен.

## Запуск

Нужен Node.js 20.19+ или 22.12+ и npm. Из этой папки:

```sh
npm ci
npm run dev -- --host 127.0.0.1
```

Откройте `http://127.0.0.1:5173/`. При активной сессии откроется кабинет, иначе — вход. `/register` открывает регистрацию, `/login` — вход, `/demo` — выбор демо-профиля, `/account` — текущий профиль. Неизвестный адрес показывает экран 404.

Маршруты кабинета: `/workspace/protocols` — журнал, `/workspace/protocols/:runId` — подробности испытания, `/workspace/roles` — матрица, `/workspace/users` — участники и назначение ролей. Без сессии защищённые страницы переводят на вход. Прямой переход Оператора или Диагноста к участникам показывает отказ в доступе.

## Что работает

- Регистрация с валидацией по API 0.2: логин 3–32 символа без обрезки пробелов, пароль от 8 кодовых точек Unicode с буквами обоих регистров, цифрой и спецсимволом.
- Проверка уникальности логина без учёта регистра. Имена `operator_01`, `diagnostics_01`, `architect_01`, `student` заняты подготовленными профилями.
- Вход в зарегистрированный аккаунт по логину и паролю, в том числе после выхода и перезагрузки страницы. Логин сравнивается без учёта регистра, пароль — точно как введён. Требования сложности при входе повторно не проверяются. Неверный пароль и неизвестный аккаунт дают одну общую ошибку.
- Демо-вход без пароля под Оператором, Диагностом и Архитектором. Профиль показывает роли и права из ответа API. Переключение демо-профиля заменяет текущую сессию.
- Вкладки регистрации, входа и демо используют одну плашку одинаковой высоты и одну 3D-сцену. Если содержимое не помещается, прокручивается форма. Ожидающий запрос отменяется при уходе со вкладки.
- Состояния ожидания, ошибок и успеха. Повторная отправка во время запроса заблокирована. После успеха пользователь сам открывает кабинет, чтобы успеть увидеть реакцию робота.
- Назначение роли Оператора при регистрации, восстановление сессии после обновления страницы и выход.
- Журнал трёх протоколов и подробности испытаний: описание, дата, результат, проверяющий и время решения. Оператор только читает. Диагност и Архитектор могут принять протокол или вернуть его на доработку. Повтор уже установленного решения сохраняет прежнего автора и время.
- Матрица ролей и действующих прав. Архитектор назначает любые непустые сочетания ролей любому участнику, в том числе себе и демопрофилям. Права складываются без повторов. После сохранения приложение перечитывает `/me`; при снятии своего права управления сразу закрывает редактор и возвращает к протоколам.
- В кабинете постоянные боковая навигация и робот по пояс; прокручивается рабочая область. На телефоне навигация располагается над содержимым, идентификатор протокола — под названием испытания. Отмена запросов и защита от поздних ответов сохраняются при смене пользователя или его прав.
- Исходный робот без постамента: взгляд за курсором и фокусом формы, отвод взгляда при открытом пароле, плавные эмоции и жесты успеха/ошибки.
- Локальные шрифты с кириллицей, адаптивная компоновка, клавиатурный фокус и учёт `prefers-reduced-motion`. Если WebGL или модель недоступны, форма продолжает работать.

## Моки и подключение API

По умолчанию `src/api/client.ts` выбирает mock-реализации `authApi` и `workspaceApi`. Задержка авторизации — 720 мс, операций кабинета — 420 мс. Форматы ответа и ошибки совпадают с [описанием API](../Docs/API.md) и [OpenAPI](../Docs/openapi.yaml).

Профили сохраняются в `localStorage` под ключом `ai-engineer.react.users.v1`; UUID текущего пользователя — в `sessionStorage` под ключом `ai-engineer.react.session.v1`. Старый HTML-макет использует отдельное хранилище. Открытый пароль не сохраняется: для новых регистраций мок хранит соль и проверочное значение PBKDF2-SHA256. Закрытие вкладки завершает демосессию, но профиль и возможность входа по паролю остаются.

Содержимое пользовательского хранилища теперь имеет версию 2. Старый формат версии 1 читается без удаления профилей и сессий. У старых аккаунтов не было проверочных данных пароля, поэтому войти в них по паролю нельзя; для такой проверки зарегистрируйте новый учебный аккаунт. При следующей успешной регистрации старые данные сохраняются вместе с новыми в версии 2.

Подготовленные аккаунты входят через `/demo`, пароль им не назначается:

| Профиль | Начальная роль | Права |
|---|---|---|
| `operator_01` | Оператор | Чтение протоколов |
| `diagnostics_01` | Диагност | Чтение и проверка протоколов |
| `architect_01` | Архитектор | Чтение, проверка протоколов, назначение ролей |

Мок также принимает `student` по контракту API. Демо-вход возвращает сохранённые роли аккаунта; выбранная карточка не назначает роль заново. При отсутствии подготовленного аккаунта возвращается 404, при неизвестном коде — 422. Неудачный вход сохраняет предыдущую сессию.

Протоколы сохраняются отдельно в `localStorage` под ключом `ai-engineer.react.runs.v1`. Роли сохраняются в существующем хранилище пользователей вместе с проверочными данными паролей. Каждый защищённый вызов мока проверяет текущую сессию и актуальные права; скрытие кнопки в интерфейсе не заменяет эту проверку. Снятие своих прав и редактирование демопрофилей разрешены. Для проверки собственной демоции удобно заранее назначить другого Архитектора.

Mock-данные можно менять в браузере: они служат демонстрации интерфейса. Мок имитирует проверку прав сервера, а настоящую защиту доступа и сессию реализует backend.

Для работы с backend при запуске Vite:

```sh
VITE_API_MODE=http npm run dev -- --host 127.0.0.1
```

Тогда клиент использует все 11 маршрутов контракта: авторизацию, `/me`, матрицу ролей, список и подробности протоколов, проверку испытаний, список участников и замену их ролей. Vite проксирует `/api` на `http://127.0.0.1:8000`; код экранов менять не требуется. Для production значение задаётся при сборке. Backend реализован в этом репозитории, режим HTTP проверен через Vite-прокси и Docker Compose.

## Структура

```text
src/app/                     маршруты через App, контекст и восстановление сессии
src/pages/                   AuthLayout, WorkspaceLayout, страницы входа и профиля
src/features/registration/   форма регистрации и правила валидации
src/features/auth/           вход, демо-профили, общее поле пароля и каталог ролей
src/features/protocols/      журнал, подробности и проверка испытаний
src/features/roles/          матрица и назначение ролей участникам
src/components/layout/      общий каркас окна
src/components/workspace/   состояния загрузки/ошибок и реакции робота
src/components/robot/       React-обёртка и контроллер Three.js
src/api/                     HTTP-клиент, моки и ошибки
src/types/                   типы API
src/styles/                  оформление из утверждённого макета
public/assets/               GLB, локальные шрифты и SVG
```

3D-код загружается отдельными чанками после кода формы. Каждая сцена освобождает WebGL-ресурсы и обработчики при размонтировании, включая React StrictMode.

## Проверка

```sh
npm run lint
npm test
npm run build
```

Тесты проверяют контракт валидации и HTTP-адаптеров, регистрацию и авторизацию, сохранение сессии, совместимость хранилища, отсутствие открытого пароля, RBAC на уровне моков, несколько ролей, снятие своих прав, неизменность повторного решения, сбои записи и отмену запросов. UI-тесты включают поздние ответы при смене аккаунта/полномочий и сбой проверки `/me` после сохранения. HTTP-проверки используют mock fetch; интеграция с реальным backend проверена через Vite-прокси и Docker Compose.

Полный стенд с реальным backend запускается через `docker compose`, инструкция — в корневом README. Демо-режим на моках остаётся доступен по умолчанию.
